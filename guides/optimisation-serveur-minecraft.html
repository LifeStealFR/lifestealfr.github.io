1. Comprendre les 20 TPS et le MSPT

Le moteur de Minecraft est cadencé par une boucle de tick : un serveur en parfait état de fonctionnement exécute exactement 20 ticks par seconde (20 TPS), soit 1 tick toutes les 50 millisecondes.

L'indicateur le plus précis de la santé de votre serveur n'est pas le TPS (qui est une moyenne différée), mais le MSPT (Milliseconds Per Tick) :

  • MSPT < 40 ms : Performances idéales, le serveur dispose d'une marge de calcul de 20%.
  • MSPT entre 45 et 50 ms : Charge limite, risque d'apparition de micro-saccades en PvP.
  • MSPT > 50 ms : Le serveur est en surcharge critique, le TPS commence à chuter en dessous de 20.

2. Les Flags JVM Aikar Flags (Java 21+)

L'utilisation des Aikar Flags avec le ramasse-miettes (Garbage Collector) G1GC est indispensable pour éviter les pauses de GC (GC pauses) qui figent le serveur pendant plusieurs centaines de millisecondes. 

java -Xms12G -Xmx12G -XX:+UseG1GC -XX:+ParallelRefProcEnabled -XX:MaxGCPauseMillis=200 \
-XX:+UnlockExperimentalVMOptions -XX:+DisableExplicitGC -XX:+AlwaysPreTouch \
-XX:G1NewSizePercent=30 -XX:G1MaxNewSizePercent=40 -XX:G1ReservePercent=20 \
-XX:G1HeapWastePercent=5 -XX:G1MixedGCCountTarget=4 -XX:InitiatingHeapOccupancyPercent=15 \
-XX:G1MixedGCLiveThresholdPercent=90 -XX:G1RSetUpdatingPauseTimePercent=5 \
-XX:SurvivorRatio=32 -XX:+PerfDisableSharedMem -XX:MaxTenuringThreshold=1 \
-Dusing.aikars.flags=https://mcflags.emc.gs -Daikars.new.flags=true \
-jar paper-1.21.jar --nogui

3. Optimisation de server.properties

Paramètre Valeur par défaut Valeur Optimisée Impact Performance
view-distance 10 6 - 8 Réduit drastiquement le nombre de chunks chargés simultanément.
simulation-distance 10 4 - 5 Limite les ticks d'entités aux seuls chunks proches des joueurs.
network-compression-threshold 256 512 Soulage le CPU en compressant moins de petits paquets réseau.

4. Configuration experte : paper-world-defaults.yml

Depuis les versions 1.19+, Paper centralise la configuration des mondes dans le dossier config/paper-world-defaults.yml. Voici les ajustements recommandés pour un serveur multijoueur haute charge : 

chunks:
  auto-save-interval: 6000 # Sauvegarde toutes les 5 min au lieu de 45 sec
  max-auto-save-chunks-per-tick: 8
  prevent-moving-into-unloaded-chunks: true

entities:
  spawning:
    despawn-ranges:
      monster:
        soft: 28
        hard: 56
    per-player-mob-spawns: true # Répartition équitable des monstres par joueur

tick-rates:
  sensor:
    villager:
      secondarypoisensor: 80 # Réduit les calculs des villageois
  behavior:
    villager:
      validatenearbypoi: 60

5. Réglages des entités dans spigot.yml et bukkit.yml

Dans spigot.yml :

  • entity-tracking-range.players: 48 (au lieu de 48-64)
  • entity-tracking-range.monsters: 32 (au lieu de 48)
  • merge-radius.item: 4.0 (fusionne les items au sol pour réduire le nombre d'entités)
  • merge-radius.exp: 6.0 (fusionne les orbes d'expérience)

6. Outils de Profilage : Spark & Timings

Pour diagnostiquer précisément la cause d'une baisse de TPS sur votre serveur en production :

  1. Installez le plugin officiel Spark (ou tapez /spark health).
  2. Lancez un profilage en direct pendant les heures de pointe : /spark sampler --duration 60.
  3. Analysez le rapport généré pour identifier les entités, chunks ou plugins monopolisant le CPU.
