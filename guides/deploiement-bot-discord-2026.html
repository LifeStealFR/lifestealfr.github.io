Déploiement Bot Discord 24/7 : Architecture, PM2, Docker et Production

✍️ Rédigé par l'équipe Tech LifeStealMC 📅 23 Septembre 2026 ⏱️ Temps de lecture : 11 min

  • 4. Déploiement Professionnel avec PM2 (Process Manager)

Développer un bot Discord sur son ordinateur local avec node index.js est parfait pour les tests. Cependant, lorsqu'il s'agit d'offrir une expérience fluide à des centaines ou des milliers de joueurs sur une communauté Minecraft ou LifeSteal, un bot doit tourner sans interruption 24h/24, résister aux micro-coupures de l'API Discord, et redémarrer automatiquement après une erreur inattendue.

1. Prérequis et Architecture Recommandée

Pour assurer une disponibilité de 99.9%, évitez d'héberger votre bot sur votre PC personnel ou sur des plateformes éphémères gratuites qui mettent le processus en veille après quelques minutes d'inactivité. Voici l'environnement recommandé :

  • Runtime : Node.js version 20 LTS ou 22 LTS (évitez les versions impaires en production).
  • Système d'exploitation : Linux Ubuntu Server 22.04 / 24.04 LTS ou Debian 12.
  • Ressources minimales : 1 vCPU, 512 Mo à 1 Go de RAM (largement suffisant pour un bot servant jusqu'à 50 000 membres si le cache est optimisé).
  • Gestionnaire de variables : Fichier .env non synchronisé sur Git (protégez impérativement votre DISCORD_TOKEN).

2. Configuration des Gateway Intents (Discord.js v14)

Depuis la v14 de Discord.js, les Gateway Intents doivent être déclarés explicitement. Demander trop d'intents inutiles surcharge la mémoire vive et consomme du trafic réseau inutile. Ne déclarez que ceux dont votre bot a rigoureusement besoin :

// bot.js - Initialisation optimisée Discord.js v14+ const { Client, GatewayIntentBits, Partials } = require('discord.js'); require('dotenv').config(); const client = new Client({ intents: [ GatewayIntentBits.Guilds, GatewayIntentBits.GuildMessages, GatewayIntentBits.GuildMembers, // Requis pour l'accueil/rôles automatiques (Privileged Intent) GatewayIntentBits.MessageContent // Uniquement si vous lisez le texte des messages (Privileged Intent) ], partials: [Partials.Message, Partials.Channel, Partials.Reaction], sweepers: { // Nettoyage périodique du cache pour éviter les fuites mémoire messages: { interval: 3600, lifetime: 1800 } } }); client.once('ready', () => { console.log(`[BOT] Connecté sous l'identifiant ${client.user.tag}`); }); client.login(process.env.DISCORD_TOKEN);
⚠️ Attention aux Privileged Gateway Intents

Si votre bot a besoin de GuildMembers ou MessageContent, vous devez impérativement les activer dans le Discord Developer Portal sous l'onglet Bot → Privileged Gateway Intents, sous peine de recevoir une erreur Disallowed Intents au lancement.

3. Gestion Robuste des Exceptions et Crashs

Une promesse rejetée sans catch (Uncaught Promise Rejection) peut faire crasher instantanément tout le processus Node.js. Pour éviter cela, écoutez systématiquement les gestionnaires d'erreurs globaux :

// Gestion globale des exceptions pour empêcher l'arrêt inopiné process.on('unhandledRejection', (reason, promise) => { console.error('[ANTI-CRASH] Promesse rejetée non gérée :', reason); }); process.on('uncaughtException', (err, origin) => { console.error(`[ANTI-CRASH] Exception non interceptée : ${err.message}`); console.error(origin); });

4. Déploiement Professionnel avec PM2 (Process Manager)

PM2 est le gestionnaire de processus standard pour Node.js. Il surveille le bot, le relance instantanément s'il plante, redémarre le bot au reboot de la machine physique, et conserve un historique détaillé des logs.

Installation et Démarrage :

# 1. Installation globale de PM2 npm install -g pm2 # 2. Démarrage du bot avec attribution d'un nom pm2 start index.js --name "lifesteal-discord-bot" # 3. Sauvegarde de la liste des processus actifs pm2 save # 4. Configuration du démarrage automatique au boot du serveur pm2 startup

Commandes Utiles PM2 :

  • pm2 logs lifesteal-discord-bot : Voir les logs console en direct.
  • pm2 restart lifesteal-discord-bot : Redémarrage à chaud.
  • pm2 monit : Interface graphique dans le terminal affichant la RAM et le CPU en temps réel.

5. Conteneurisation Docker & Fichier Compose

Pour un déploiement 100% reproductible et isolé, la conteneurisation avec Docker est la solution idéale :

# Dockerfile FROM node:20-alpine WORKDIR /app COPY package*.json ./ RUN npm ci --only=production COPY . . CMD ["node", "index.js"]

Et votre fichier docker-compose.yml :

version: '3.8' services: discord-bot: build: . container_name: bot-production restart: unless-stopped env_file: - .env mem_limit: 512m

6. Déploiement sur Panel Pterodactyl

Si vous utilisez un hébergeur gaming ou un panel Pterodactyl (NodeJS Generic Egg) :

  1. Définissez index.js ou bot.js comme Main File dans les paramètres de démarrage.
  2. Vérifiez que la version de Node.js sélectionnée dans le panel est au minimum la version 18 (idéalement 20 ou 22).
  3. Ne committez jamais le dossier node_modules : laissez le panel exécuter npm install lors de l'installation.

7. Bonnes Pratiques de Monitoring et Rate Limits

L'API Discord impose des limites de requêtes (Rate Limits) strictes :

  • 50 requêtes par seconde par route globale. Évitez d'envoyer des messages en boucle infinie sans délai.
  • Ne stockez pas de tokens d'authentification en clair dans le code. Utilisez impérativement process.env.DISCORD_TOKEN.
  • Mettez en place un Webhook d'alerte : En cas d'erreur critique, votre gestionnaire d'exception peut envoyer un embed sur un salon privé réservé aux administrateurs.
